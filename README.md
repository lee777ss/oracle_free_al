# Oracle-Free Active Learning: A Confidence-Gated Generative Augmentation Framework for Imbalanced Classification

Code and per-run results behind the manuscript KNOSYS-D-26-20956 (*Knowledge-Based Systems*, revision),
by Kyung-Sun Lim, Wonjae Lee and Jae-Hyuk Choi.

The repository contains the code exactly as it was run, the random seeds, and the per-run results of every
experiment reported in the paper, so that each table can be recomputed from the saved results or re-run
from scratch.

## Contents

| Path | What it is |
|---|---|
| `casestudy/` | Data pipeline, classifiers, the proposed method (`methods/m10_ab8c.py`) and the generative rivals (Sections 3, 4.2, 4.4) |
| `cs3j_runner.py` | Regime definitions and the runner of the submitted case-study experiments |
| `ablation/`, `bagan/`, `bagan_gp/` | Pipeline and backbones of the ablation study (Table 3, panel A) |
| `notebooks/` | `GAAL_Ablation_133J.ipynb` (one ablation run per seed and backbone) and `311_Ablation_15_seeds.ipynb` (aggregation over seeds 42-56); outputs stripped |
| `kbs2/` | Experiments and analyses added in the revision (runner, statistics, tables) |
| `kbs/` | Helpers from an earlier stage of the revision used by `kbs2` (reference classifiers) |
| `saved_casestudy/` | Per-seed results of the submitted experiments behind Tables 6 and 7 |
| `ablation_15_seeds.csv` | Per-seed results of the ablation study (Table 3, panel A) |
| `saved_kbs2/` | Per-run results (`<experiment>/runs.csv`), test-set predictions and analysis outputs of the revision experiments |

Only the results reported in the paper are included. Generated images and trained networks are not
distributed; they are regenerated by the code.

## Environment

The experiments were run with Python 3.11.15, PyTorch 2.11.0 (CUDA 12.8) and NumPy 2.4.3 on a single
NVIDIA GeForce RTX 5090.

```
conda create -n oracle_free_al python=3.11
conda activate oracle_free_al
pip install torch==2.11.0 torchvision==0.26.0 --index-url https://download.pytorch.org/whl/cu128
pip install -r requirements.txt
```

Run every command from the repository root. Fashion-MNIST, CIFAR-10 and STL-10 are downloaded by
`torchvision` into `./data/` on first use; the class subsets and imbalance ratios of each regime are
defined in `cs3j_runner.py` (`REGIMES`) and `kbs2/protocol.py`.

Commands marked *recompute* read the results saved in this repository and take minutes on a CPU; commands
marked *re-run* repeat the experiment (GPU).

| Table 3, panel B | mean and SD over seeds of `saved_kbs2/AB/runs.csv`, grouped by `tag` (`<rule>_nocot`); tests in `saved_kbs2/analysis/AB/`; seed-to-seed SD: `python -m kbs2.ab_stability` | `python -m kbs2.runner run AB`, then `python -m kbs2.ab_analysis` |
| Table 4, Figure A2 (FID) | `python -m kbs2.ablation_fid_table` (reads `ablation_15_seeds.csv` and `saved/ae_fid_133J_*.npz`) | as Table 3, panel A |
| Figure A1 | `python -m kbs2.ablation_figure` | as Table 3, panel A |
| Figure 2 (ablation samples) | — | as Table 3, panel A (the notebook writes the sample dumps to `saved/`), then `python -m kbs2.ablation_samples` |
| Table 6 | rows in `saved_casestudy/cs3j_*_reduced8.csv` (seven submitted methods) and `saved_kbs2/E2t`, `E2z`, `E2s` (simple remedies) | `python -m kbs2.runner run E1` (proposed), `E8` (generative rivals), `E2` (naive baseline), `E2t`, `E2z`, `E2s` |

Every run uses the seeds stated in the paper (42-51 for the case studies, 42-56 for the ablation); the
downstream classifier is initialised with seed 42 as in the submitted protocol (`kbs2/protocol.py`,
arm `W`).

`kbs2.ab_analysis` expects the complete experiment AB (sixteen arms); the `runs.csv` released here holds the
arms the paper reports, so recompute its statistics after re-running AB.

## Provenance guard

`kbs2/provenance.py` checked, before every run of the revision experiments, that the code was byte-identical
to the submission snapshot and that the environment matched the recorded one, and `kbs2/runner.py` required
an approval record for each experiment. The snapshot and the approval records belong to the authors'
working repository and are not part of this one, so in this release both checks print a warning instead of
stopping the run. Nothing that affects the computation is changed.
